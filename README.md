# YouTube Player Lab

Official YouTube player for ChatGPT MCP Apps (no downloading or proxying video).

Routes after deployment: `/health`, `/player` (video only), `/popout` (standalone window/tab player), `/diagnostics` (separate diagnostic player), `/mcp` (ChatGPT MCP).

Deploy on Render using Node, `npm install --omit=dev`, `npm start`.

YouTube embedding can fail inside ChatGPT due to frame restrictions or referrer policy even when Safari standalone playback succeeds. Playback must be explicitly verified.

## Conversational assistant (0.2)

- `search_youtube_videos`: reads actual public search results. ChatGPT uses the conversation it can access to choose results and explain recommendations; the server does not collect chat history.
- `open_youtube_player`: creates a two-hour player session. Its `playerRef` lets the model reuse the same player through `control_youtube_player` (`select`, `play`, `pause`, `seek`). `get_youtube_player_state` reports actual video/time/state and freshness; queuing a command never proves playback.
- `get_youtube_transcript`: retrieves public timestamped caption text without downloading video or audio. It uses the public web-client caption path, which is unofficial and can change or be blocked. It requires no Gemini or user API key. Missing captions and access restrictions are explicit errors. Language and automatically generated status accompany the source. Follow `nextCursor` for long transcripts; a partial page is not the full video.
- For a question about the current player, check its fresh observed video and pass both `playerRef` and `videoId` to the transcript tool. A concurrent switch invalidates the result instead of returning the old video's speech as current content.
- Reporting credentials remain in UI-only `_meta` and same-origin headers. The external player passes them to its own iframe in a URL fragment, never a query or YouTube URL. The most recently attached player takes control and the old surface pauses. These expiring capabilities are for the personal experiment, not account authentication. Restarting the free Render instance loses active sessions; reopen the player to reconnect.

Refresh the custom plugin after deploying changed tool schemas and rerun the player for `ui://youtube-player-lab/conversation-v6.html`. Mac and mobile behavior require separate live verification; unit tests do not establish either device's playback or autoplay policy.

## Player layout and separate window

The normal view contains the official YouTube player plus a compact toolbar outside the video. The wrapper and hosted page fill the available viewport without fixed pixel heights, outer margins, or document scrolling. Both iframe boundaries explicitly delegate fullscreen before navigation. Native YouTube fullscreen and the host app's fullscreen display mode are separate; a host restriction cannot be overridden by the child page. The earlier diagnostic UI remains available at `/diagnostics`.

- **팝업:** opens the selected video in the standalone `/popout?videoId=...` player through the host's external-link API, with a normal browser popup fallback outside embedded hosts.
- **팝업 후 전체화면:** opens the same page with `fullscreen=1`. The standalone document tries its own fullscreen API once. If the browser requires a new user gesture, its **전체화면 시작** button provides that gesture.
- **직접 열기:** a normal new-tab link available after an opening request or error. It never redirects to an arbitrary tool-supplied URL.

The component initializes the standard MCP Apps bridge and prefers `ui/open-link` when advertised. `window.openai.openExternal` is a feature-detected compatibility fallback; only the player's own origin is allowlisted. It does not request ChatGPT PiP or ChatGPT fullscreen. Buttons prevent overlapping requests and expose a manual link after rejected, unconfirmed, or timed-out requests rather than automatically opening duplicate tabs. A host acknowledgement proves an opening request was accepted, not that a separate window appeared. The browser/host chooses whether a link becomes an external window, tab, or an in-app surface; actual native behavior must be checked. The toolbar does not intercept or cover YouTube's native fullscreen button. Unit tests with a simulated host verify requests, not window placement or fullscreen rendering.

## Error 153 diagnostics

- YouTube defines 153 as a missing HTTP Referer or equivalent API client identity. It is separate from autoplay blocking and video embedding errors 101/150.
- The MCP resource embeds the same server's HTTPS `/player` page, declared as the only outer CSP `frameDomains` destination. The hosted page has its own document origin and declares `strict-origin-when-cross-origin`. YouTube's generated iframe also uses this policy in the observed environment. A configured policy is not proof that a request sent a Referer.
- Diagnostics distinguish the URL origin (`location.origin`) from the effective execution origin (`window.origin`). An opaque execution origin is reported as `null`; it is not replaced with an invented Render origin in player parameters.
- The incoming `document.referrer` identifies the referring page, not the header sent to YouTube. Only its origin is logged. An opaque sandbox may prevent an outgoing referrer even with the declared policy; another nested iframe cannot relax an ancestor's sandbox.
- Start playback with YouTube's own center play button. A separate API play button can be blocked by the host's autoplay policy. `onReady` is initialization only. Verify `onStateChange 1` plus increasing playback time before reporting success.
- The wrapper relays only a validated video ID from the MCP host to the exact player origin, including notifications received before the hosted frame loads. Other tool-result content is not forwarded.
- Existing ChatGPT cards can retain earlier HTML. Refresh the custom plugin and rerun it to use `ui://youtube-player-lab/external-window-v5.html`. Previous resource URIs remain available for compatibility. The diagnostic route shows version `referrer-20261017-1`.

Observed on 2026-10-17 before the HTTPS wrapper: the existing card in ChatGPT web on Mac played for over 18 seconds and paused correctly after enabling CSP enforcement. The native Mac MCP Apps viewer reproduced error 153 with a `codex-sandbox://` URL origin, an empty incoming referrer, and an iframe already configured with `strict-origin-when-cross-origin`. This is evidence of a host-environment difference, not a direct capture of the outgoing HTTP header. Custom-scheme referrer handling needs investigation in the native host. The wrapper is a targeted mitigation: a network-loaded HTTPS child can supply its own origin if the ancestor sandbox permits it. An inherited opaque-origin restriction could still prevent playback. Native playback must be verified for the newly loaded wrapper before claiming success.

After deploying the HTTPS wrapper, the native Mac viewer's hosted player reported both URL and execution origin as `https://youtube-player-lab.onrender.com`. Playback emitted `onStateChange 1`, and the actual video element advanced from 2.457856 to 21.66092 seconds with `paused: false`; pressing pause produced `paused: true` at 21.714547 seconds. The user also confirmed playback. This verifies the tested Mac environment, not every browser or mobile host, and does not directly capture the outgoing Referer header.

After the video-only layout deployment on 2026-10-17, the user confirmed that unwanted scrolling was gone. Fullscreen remains unresolved in the native Mac host: pressing YouTube's fullscreen button makes the ChatGPT app fullscreen without isolating the video. Standalone in-app-browser testing showed the YouTube fullscreen button switching to its exit state, but that does not verify native-host video-only fullscreen. Both iframe boundaries already delegate fullscreen, and the YouTube player uses `fs=1`. The host's handling of HTML fullscreen is a suspected cause, not a verified implementation detail. The SDK's `requestDisplayMode({mode: "fullscreen"})` is a separate host layout and [keeps the ChatGPT composer visible](https://developers.openai.com/plugins/concepts/ui-guidelines#fullscreen), so it is not a verified fix for this symptom. Do not describe native video-only fullscreen as fixed.

After the popup controls deployment, the user reported disabled or non-working popup buttons. In the native Mac MCP Apps panel, DOM inspection confirmed `displayBridge=mcp`, `displayMode=fullscreen`, both popup buttons disabled, and the inline button enabled. This combination means the host's advertised `availableDisplayModes` omitted `pip`; it is not an observed rejection of a PiP request, since the disabled controls prevented that request. The unsupported-mode message was being cleared by an unrelated `openai:set_globals` notification. The status fix retains that explanation until supported modes change and exposes the latest advertised modes in a DOM dataset for verification. Native Mac pinned popup and video-only fullscreen remain unverified/unsupported by the observed host context.

After deploying the status fix, the native panel directly reported `availableDisplayModes=inline,fullscreen`, `displayBridge=mcp`, and `displayMode=fullscreen`. The unsupported-popup explanation stayed visible with popup buttons disabled and the inline button enabled. The panel's scroll and client dimensions were both 463×702. This verifies the status fix and the observed host's advertised limitation; it does not establish that every ChatGPT host or a future native version lacks PiP.

The user subsequently clarified that popup means a separate browser window/tab, not a pinned ChatGPT surface. In local Chrome testing of the replacement flow, the popup button created a separate `/popout` tab with the selected video and `fullscreen=1`. Automatic fullscreen was denied; a manual click switched the standalone player's fullscreen button to `aria-pressed=true`, hid its toolbar, and filled its 1920×873 content viewport without scrolling. The actual YouTube video advanced to 19.650114 seconds with `paused=false` and `readyState=4`. A native Chrome screenshot still showed browser UI, so that local test alone was not proof of physical video-only screen coverage or native ChatGPT external routing.

Production verification of the native Mac card then reported `externalBridge=mcp` and `hostOpenLinks=true`. Clicking **팝업** opened the production `/popout?videoId=M7lc1UVf-VE` page in an external Chrome tab, with no new in-app-browser tab. Clicking **팝업 후 전체화면** opened another external Chrome tab including `fullscreen=1`. Automatic fullscreen was denied, but a native click on the new page's fullscreen button hid Chrome's address/tab bars and the player's toolbar; the automation debugger infobar remained visible. Escape restored the browser UI and player toolbar. The actual video advanced to 10.555684 seconds, with `paused=true` after pausing and `readyState=4`. Scroll and client dimensions after exit both measured 1920×873. This verifies separate external tabs and manual fullscreen in the tested Mac/Chrome environment, not a forced separate OS window or automatic fullscreen in every browser.
